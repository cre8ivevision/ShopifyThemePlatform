# Merchant Dashboard

## 1. Purpose

This document defines the merchant dashboard experience inside the Companion App. The dashboard should help merchants understand their theme status, next actions, active features, design system, and growth opportunities.

## 2. Dashboard Principles

- Show what matters now.
- Avoid technical clutter for beginners.
- Provide deeper diagnostics for advanced users.
- Make next actions clear.
- Keep language simple and confidence-building.

## 3. Primary Dashboard Sections

| Section | Purpose |
|---|---|
| Setup Progress | Shows onboarding and configuration completion |
| Active Design | Shows selected skin, template, and design mode |
| Feature Manager | Shows enabled, available, and recommended features |
| Store Health | Shows performance, accessibility, and sync health |
| Recommendations | Shows suggested next improvements |
| Licensing | Shows plan and premium access |

## 4. User Modes

The dashboard should adapt to:

- Beginner merchant
- Growing merchant
- Designer
- Developer
- Agency

## 5. Empty States

Empty states should be helpful and action-oriented.

Examples:

- No skin selected: recommend starting with Minimal Mono.
- No premium features enabled: explain available growth options.
- Sync failed: show recovery action.

## 6. Dashboard Actions

Common actions:

- Continue onboarding
- Change skin
- Install template pack
- Enable feature
- Review recommendation
- View sync status
- Open theme editor

## 7. Acceptance Criteria

- Dashboard provides clear current state.
- Dashboard supports beginner and advanced users.
- Recommendations are visible but not overwhelming.
- Health and sync states are understandable.
