# Documentation Standards

## 1. Purpose

This document defines standards for writing and maintaining documentation in the Shopify Theme Platform repository. Consistent documentation helps humans and AI assistants understand, extend, and maintain the platform.

## 2. Language and Format

- Documentation should be written in official English.
- Markdown should be used for all repository documents.
- Document titles and IDs must remain stable.
- Links should be relative where practical.
- Tables should be used for structured requirements.

## 3. Standard Document Sections

A standard document should include:

- Document metadata
- Purpose
- Scope
- Principles
- Requirements or architecture
- Acceptance criteria
- Related documents
- Revision history

## 4. Naming Rules

Files should use lowercase kebab-case.

Example:

```text
61-ai-development-guide.md
```

## 5. Revision History

Every document should include a revision history table with:

- Version
- Date
- Author
- Description

## 6. Cross-Linking

Documents should reference related documents when they depend on shared decisions, architecture, or implementation rules.

## 7. Maintenance Rules

Documentation should be updated when:

- Architecture changes
- Product decisions change
- APIs change
- Component behaviour changes
- New ADRs are accepted

## 8. Acceptance Criteria

- Documents use consistent structure.
- Document IDs are preserved.
- Related documents are linked.
- Index files remain updated.
- Revision history is included.
