# Bug Classification

## 1. Purpose

This document defines how bugs should be classified for the Shopify Theme Platform. Clear classification helps prioritise fixes, communicate risk, and protect merchant trust.

## 2. Severity Levels

| Severity | Meaning |
|---|---|
| Critical | Storefront or checkout-impacting issue with major business risk |
| High | Important feature broken or major merchant workflow blocked |
| Medium | Noticeable issue with workaround available |
| Low | Minor visual, copy, or edge-case issue |

## 3. Bug Categories

| Category | Examples |
|---|---|
| Functional | Broken component or setting |
| Visual | Layout or styling defect |
| Accessibility | Keyboard, contrast, semantic issue |
| Performance | Slow loading or heavy asset issue |
| Compatibility | Browser or device-specific issue |
| Documentation | Incorrect or missing documentation |
| App | Licensing, sync, dashboard, or API issue |

## 4. Priority Factors

Priority should consider:

- Merchant impact
- Shopper impact
- Revenue risk
- Frequency
- Workaround availability
- Release proximity
- Support volume

## 5. Bug Report Requirements

A bug report should include:

- Summary
- Expected behaviour
- Actual behaviour
- Steps to reproduce
- Environment
- Screenshots or logs where useful
- Severity suggestion
- Related documents or components

## 6. Acceptance Criteria

- Severity levels are defined.
- Bug categories are documented.
- Priority factors are clear.
- Bug reports have required fields.
