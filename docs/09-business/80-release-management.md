# Release Management

## 1. Purpose

This document defines release management principles for the Shopify Theme Platform. Releases should be planned, documented, tested, and communicated clearly to protect merchant trust.

## 2. Release Principles

- Releases should be intentional and versioned.
- Breaking changes should be avoided where possible.
- Merchants should understand what changed.
- QA should happen before release.
- Documentation should be updated with releases.

## 3. Release Types

| Type | Description |
|---|---|
| Patch | Bug fixes and minor corrections |
| Minor | New non-breaking features |
| Major | Significant architecture or behaviour changes |
| Skin Release | New or updated design skin |
| Template Release | New template or preset pack |
| App Release | Companion app feature release |

## 4. Release Checklist

A release should include:

- Scope summary
- Version number
- QA status
- Documentation updates
- Known issues
- Migration notes if needed
- Support notes

## 5. Communication

Release communication may include:

- Changelog
- App dashboard notice
- Email update
- Documentation update
- Marketplace update notes

## 6. Acceptance Criteria

- Release types are defined.
- Release checklist is documented.
- Documentation updates are part of release process.
- Merchant communication is considered.
